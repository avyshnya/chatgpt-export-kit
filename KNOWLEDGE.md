# KNOWLEDGE — довідник методу і граблів

Стислий конденсат досвіду реального вивантаження: ~1000 чатів, 18 проєктів,
сотні вкладень із робочого простору ChatGPT Business. Кожен пункт тут —
перевірений факт, а не припущення. Спростовані міфи позначені окремо.

## Метод у одному абзаці

Офіційний експорт у ChatGPT Business недоступний («Data export is not
available in a Business workspace» — без винятку навіть для Owner);
Compliance API — лише Enterprise/Edu; штатний флоу експорту не завершується
(код підтвердження приходить, лист із посиланням — ні). Робочий шлях:
запити до внутрішнього API chatgpt.com **зсередини власної залогіненої
вкладки Chrome**. Токен — `GET /api/auth/session` → `accessToken`. Простір
задає заголовок `ChatGPT-Account-ID` (значення — з `accounts/check`; для
особистого простору заголовок не потрібен). Дані йдуть маршрутом
API → пам'ять сторінки → Blob → файл у `~/Downloads`; через модель (Claude)
текст не проходить — спотворення виключене конструктивно; кожен крок
звіряється sha256.

## Ендпоінти

| Ендпоінт | Призначення |
|---|---|
| `/backend-api/accounts/check/v4-2023-04-27` | простори і роль; звідси account id |
| `/backend-api/gizmos/snorlax/sidebar?conversations_per_gizmo=1` | перелік проєктів + інструкції (промпти) + файли рівня проєкту |
| `/backend-api/gizmos/{gizmo_id}/conversations?limit=50` | чати проєкту (курсорна пагінація) |
| `/backend-api/conversations?offset=N&limit=100` | всі чати простору (АЛЕ без архівованих) |
| `/backend-api/conversation/{id}` | повне дерево розмови — ГОЛОВНИЙ лімітований ендпоінт |
| `/backend-api/files/{id}` | метадані файлу = дешевий детектор живості (без байтів) |
| `/backend-api/files/download/{id}?inline=false` | завантаження файлу (id ПІСЛЯ `download`) |
| `/backend-api/conversations/search?query=` | пошук; рятує, коли `conversation/{id}` таймаутить |
| `/backend-api/conversation/{id}/interpreter/download` | файли code interpreter (окремий маршрут) |

## Лімітер (найдорожчі знання)

- `/backend-api/conversation/{id}`: сталий темп ~1 запит/1,5–1,75 с працює
  без жодного 429. **Сплеск вибиває запас** → акаунт падає у штрафне вікно,
  де навіть 1 запит/3 с ловить 429. Вихід — тільки тиша або дуже довгі
  інтервали; ретраї та зменшення інтервалу поглиблюють яму. Реальний прогін:
  12×429 за прохід, інтервал виріс 5 000 → 52 000 мс і так дожив до кінця —
  0 втрат. Штрафне вікно коштує ~день.
- Числа спільноти (перевірені й у нас): інтервал за замовчуванням 1500 мс,
  backoff `(спроба+1)×5000 мс`, максимум 3 ретраї, далі пропустити.
- **Темп 1–3 чати/хв — НОРМА, а не поломка.** 600 чатів = кілька годин.
- `/backend-api/files/*`: лімітера на помірному темпі не видно (0×429 при
  1 запит/3 с), але запас не міряли — перепис живості не ганяти швидше
  1000 мс.
- Chrome **тротлить таймери фонових вкладок** — вкладку з качанням тримати
  активною на передньому плані, інакше темп рве.

## Помилки-пастки

- `limit > 50` у `gizmos/{id}/conversations` → **HTTP 422**.
- Поле `total` у видачах **бреше** (items+1) — рахувати лише пагінацією.
- **`/conversations` НЕ віддає архівовані розмови.** Архівований чат може
  прийти лише маршрутом проєктів або окремим проходом `?is_archived=true`.
  Якщо повнота критична — зробити і його.
- **`g-p-…` ≠ `g-…`**: `g-p-` — проєкт; просто `g-` — звичайний чат із
  кастомним GPT. Фільтр «є gizmo_id → проєктний» помилково викидає нормальні
  чати. Фільтрувати строго за префіксом `g-p-`.
- `gizmo_id` як query-параметр до `/conversations` **ігнорується** мовчки —
  чати проєкту брати тільки через `/gizmos/{id}/conversations`.
- **Мертві файли віддають чистий 404** `{"detail":"File not found"}` — і це
  НЕ залежить від віку файлу (файл 2024-го живий, файл 2026-го мертвий).
  Міфи «старі вкладення → 422» і «file- потребує gizmo_id, file_ — ні» —
  **спростовані**: 422 не існує, `gizmo_id` не потрібен нікому.
- **`/files/{id}` (метадані) — надійніший за сам download:** download може
  віддати `200` з порожнім тілом (виглядає як успіх, а файла нема) — і лише
  meta каже правду. Тому: спершу перепис живості, потім качання.
- Дзеркальний маршрут `/files/{file_id}/download` (id ПЕРЕД download) віддає
  `permission_error` навіть власнику — не використовувати.
- Емпірика живості: id типу `file-…` виживають значно частіше, ніж
  `file_…` — але це статистика, не правило; переписувати всі.
- Зображення (`asset_pointer`) діставані: `file_id` регуляркою
  `/file[-_][0-9a-f]+/i`; якщо вказівник — уже URL на CDN
  (`oaidalleapiprodscus.blob.core.windows.net`, `cdn.oaistatic.com`) —
  качати напряму.
- Окремий випадок: розмова може бути **завелика для серіалізації** —
  `/conversation/{id}` віддає `{"detail":"Request timeout"}` HTTP 500 через
  30 с (UI її теж не відкриває). Частково рятує `/conversations/search`;
  повні дані — лише через підтримку OpenAI. Задокументувати як втрату.

## Середовище і передача даних

- Виклики CDP (інжект JS через MCP) довші ~45 с **рвуться** — довгі цикли
  запускати фоновою задачею в сторінці (скрипти повертають `STARTED`
  одразу), стан полити короткими викликами `window.__kitSt` / `__livSt` /
  `__dlSt`.
- **В інжектованому JS — лише ASCII:** кирилиця приходить у консоль
  спотвореною (`–ø–µ—Ä…`). Той самий код, вставлений руками з буфера, — ок.
- Chrome блокує друге програмне завантаження з сайту → одноразовий дозвіл:
  Налаштування → Сайти → Автоматичні завантаження → `chatgpt.com`.
- Chrome **не перезаписує** однойменні завантаження — додає ` (1)`. Звіряти
  вміст файлу, а не ім'я. Chrome також міняє `:` в іменах на `_`; macOS
  авто-розпаковує великі `.zip`.
- **Ідентифікатори ніколи не переписувати руками в чат** (реальний випадок:
  11 переписаних file_id — всі вигадані, пілот у смітник). Тільки інжект
  чанками зі звіркою sha256 або `pbcopy` + `shasum -a 256`.
- **Один примірник скрипта.** Паралельний запуск множить темп і спалює
  запас лімітера.
- Штучний «headless» доступ не працює (бот-захист). Все — зсередини
  справжньої залогіненої вкладки.

Наприкінці нагадати користувачу про **публічні share-лінки**: Налаштування →
Керування даними → Спільні посилання → Керувати. Видалення лінка не видаляє
чат, але закриває публічний доступ (серед відкритих лінків бувають чутливі
чати — перевірити варто).
