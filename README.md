# ChatGPT Export Kit

> A portable, Claude Code-driven toolkit for fully exporting your ChatGPT
> history (Business workspace and/or personal account) — chats, project
> instructions, attachments — when the official export is unavailable.
> The interactive flow supports Ukrainian and English (you pick at start).

## Що це

Набір для **повного вивантаження історії ChatGPT** у локальний архів: усі
чати, інструкції (промпти) проєктів, прикріплені файли — з Business
workspace і/або особистого простору. Процесом керує **Claude Code** в
інтерактивному режимі: він питає, рахує, показує оцінки часу і виконує всю
технічну роботу; ви лише відповідаєте на нумеровані питання.

## Чотири категорії даних

Кіт вивантажує чотири категорії (нумерація однакова скрізь — у діалозі та в
PLAYBOOK):

1. **Проєкти** — промпт (інструкція) кожного проєкту + його чати.
2. **Чати поза проєктами.**
3. **Файли в проєктах** — документи, прикріплені до проєкту як такого.
4. **Файли в кожному конкретному чаті** — вкладення всередині розмов.

**Порада:** категорії 1 і 2 завантажуйте **обов'язково** — це легкі
мегабайти і головна цінність. Чи вантажити 3 і 4 — ваше рішення: обсяг може
бути від сотень мегабайт до терабайтів. Утиліта на кожному етапі попередить,
скільки це часу і місця, тож рішення можна ухвалювати по ходу, а пропущене —
долити пізніше другим проходом.

## Навіщо

У ChatGPT Business офіційний експорт даних **недоступний** — довідка OpenAI
каже прямо: «Data export is not available in a Business workspace», без
винятку навіть для Owner. Compliance API продається лише Enterprise/Edu.
А штатний флоу експорту не завершується: код підтвердження приходить, лист
із посиланням на архів — ні. Єдиний робочий шлях — внутрішній API
chatgpt.com **зсередини власної залогіненої вкладки браузера**. Саме його
цей кіт і автоматизує.

## Звідки виник

Кіт народився з реального вивантаження робочого простору ChatGPT Business —
**~1000 чатів, 18 проєктів, сотні вкладень** — і ввібрав усі набиті там
граблі: поведінку лімітера OpenAI (штрафні вікна), мертві файли, пастки
пагінації, брехливі поля `total`, звірки sha256, resume-safety. Все це
задокументовано в `KNOWLEDGE.md` — стисло, по факту, без припущень.

## Принципи

- **Дані не проходять через модель.** Маршрут: API → пам'ять сторінки →
  Blob → файл на диску. Кожен крок звіряється sha256 — спотворення
  виключене конструктивно.
- **Темп не форсується.** На 429 — тільки сповільнення, назавжди. Швидкість
  диктує лімітер OpenAI, і сперечатися з ним дорожче, ніж чекати.
- **Все resume-safe.** Обрив, перезавантаження вкладки, пауза на добу —
  процес продовжується з місця, нічого не втрачається.
- **Архів самодостатній.** Сирі дані лежать у `_source/`; вся структура
  (читабельні chat.md, теки проєктів) регенерується з них без доступу до
  акаунта.

**Дисклеймер:** користувач вивантажує **власні дані власного акаунта**.
Інструмент не обходить жодних механізмів захисту — він лише автоматизує те,
що користувач і так бачить у своєму браузері власними очима.

## Вимоги

- macOS
- **Claude Code** з розширенням **Claude in Chrome**
- **Python 3**
- Chrome із залогіненою вкладкою `chatgpt.com`
- Дозвіл **Multiple downloads** для `chatgpt.com` — інакше Chrome заблокує
  друге ж програмне завантаження. Увімкнути: вставте в адресний рядок Chrome
  `chrome://settings/content/automaticDownloads` → «Додати» → `chatgpt.com`
  (Claude нагадає про це на старті, робиться один раз)
- Вільне місце на диску (залежить від обсягу вкладень; орієнтир — кілька ГБ)

## Як почати — 3 кроки

1. Відкрийте нову сесію Claude Code у цій теці (десктоп-додаток або `claude`
   в терміналі — як зручніше).
2. Вставте цілком промпт із `START-PROMPT.md` (усе, що нижче риски) — або
   просто напишіть: **«прочитай START-PROMPT.md і виконуй»**.
3. Відповідайте на питання — Claude поведе далі: перевірить середовище й
   вільне місце, а перед КОЖНИМ етапом покаже три величини — кількість
   одиниць, орієнтовний обсяг на диску і час «від–до» — і спитає
   підтвердження (виконати / пропустити / зупинитися).

## ⏳ Чесне попередження про час

Темп диктує лімітер OpenAI. **~600 чатів = кілька годин** — це нормально і
за задумом. Пришвидшити неможливо: спроба гнати швидше вганяє акаунт у
«штрафне вікно», яке коштує **день** очікування. Кожен етап можна пропустити
або перервати — все зроблене зберігається, пропущене доливається пізніше.

## Вміст теки

| Файл | Що це |
|---|---|
| `README.md` | цей файл |
| `START-PROMPT.md` | промпт для запуску (копіюється в Claude Code цілком) |
| `PLAYBOOK.md` | покроковий сценарій для Claude: середовище → розвідка → чати → файли → фінал |
| `KNOWLEDGE.md` | довідник: ендпоінти, лімітер, помилки-пастки |
| `ANALYZE-PROMPT.md` | готовий промпт для аналізу ВЖЕ зібраного архіву (нова сесія в теці архіву) |
| `tools/fetch-conversations.js` | качалка розмов (браузерна консоль; resume-safe, лімітер) |
| `tools/liveness-census.js` | перепис живості вкладень (метадані, без байтів) |
| `tools/files-download.js` | качання живих файлів зі sha256-звіркою |
| `tools/unpack.py` | NDJSON → тека-на-чат (`chat.md` + `chat.json`) |
| `tools/reorg.py` | збірка структури архіву (проєкти, промпти, маніфест) |
| `tools/merge-manifest.py` | долив маніфесту вкладень зі звітів unpack |
| `tools/ingest.sh` / `tools/watch-ingest.sh` | забір готових файлів із `~/Downloads` в архів |

Скрипти в `tools/` — **шаблони без жодних персональних даних**: ідентифікатори
акаунта і списки id сідаються в сторінку під час роботи (зі sha256-звіркою) і
в кіті не зберігаються.

## Структура архіву на виході

```
<Ваш архів>/
  _source/                 сирі NDJSON + метадані + маніфест (джерело правди)
  1. Робоча — <workspace>/
    projects/<Проєкт>/
      _PROMPT.md           інструкція проєкту
      _files/              файли, прикріплені до проєкту
      <дата — назва — id8>/
        chat.md            читабельний текст розмови
        chat.json          повне сире дерево розмови
        _files/            вкладення цього чату
    no-project/<чат-тека>/ чати поза проєктами
  2. Особиста/             те саме для особистого простору
  FILES.md                 агрегатний перелік файлів
```
